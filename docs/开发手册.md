# Voicemeeter Potato 中文启动器 · 开发手册

> 项目代号：VM8CN ｜ 版本：V1.2（启动器 v8） ｜ 最后更新：2026-11-16

## 1. 项目定位

一套**不修改目标程序磁盘文件**的界面汉化方案：通过 C# 启动器以挂起方式拉起 `voicemeeter8x64.exe`，在进程恢复运行前把中文字符串按 RVA 直接写入其内存，从而实现"中文界面 + 原版程序零改动"。

| 项目 | 说明 |
| --- | --- |
| 目标程序 | Voicemeeter Potato 3.1.3.0（`voicemeeter8x64.exe`，13,548,576 字节，x64） |
| 默认安装路径 | `C:\Program Files (x86)\VB\Voicemeeter\voicemeeter8x64.exe` |
| 交付形态 | 单文件绿色启动器 `Voicemeeter8中文启动器.exe`（72,192 字节，免安装） |
| 补丁规模 | 1043 条字符串（ANSI 972 条 + UTF-16LE 71 条），blob 21,582 字节 |
| 覆盖范围 | 菜单、设置面板、对话框标题与标签、警告/错误提示、VBAN/MIDI/录音机/效果器参数、全部悬停提示 |
| 明确不覆盖 | 主界面混音台与插件面板的图形化文字（打包在 RCDATA 100–104 加密资源中，见 §8） |

### 为什么必须走内存补丁

`voicemeeter8x64.exe` 内置文件完整性校验。**只要磁盘上的 exe 被改动**（哪怕等长同字节数替换、重算 PE 校验和），程序会在启动约 10 秒后崩溃，典型异常码 `0xC0000005`（访问冲突）或 `0xC000041D`（回调中的未处理异常）。

因此本项目的核心约束是：

1. 磁盘上的 `voicemeeter8x64.exe` 一个字节都不许动；
2. 所有替换发生在目标进程**尚未执行任何程序代码**的时间窗内（挂起态）。

## 2. 使用者视角（3 步）

1. 确认 Voicemeeter 已正常安装且**当前未运行**（运行中启动器会询问是否关闭重启）；
2. 双击 `Voicemeeter8中文启动器.exe`，UAC 弹窗点「是」（manifest 声明了 `requireAdministrator`）；
3. 看到启动画面约 5 秒后进入中文界面。

注意事项：

- 以后**始终通过本启动器**启动 Voicemeeter，直接双击原版 exe 仍是英文；
- 若启动约 10 秒后崩溃，说明安装目录的 exe 之前被"直接改文件"的老办法污染过，用同目录的 `voicemeeter8x64.exe1`（安装包原始备份）还原后重试；
- 卸载＝删掉启动器 exe，无注册表、无残留、不改系统。

## 4. 技术原理

### 4.1 文本的双层结构

| 层 | 位置 | 是否可补丁 | 说明 |
| --- | --- | --- | --- |
| 字符串层 | `.rdata` / 资源中的裸 ANSI zstring 与 UTF-16LE | ✅ 本项目已覆盖 | 可用 `scan2.py` 直接 grep 到，用 `off2rva` 换算即可 |
| 图形资源层 | RCDATA 100–104，合计约 8.3 MB，数据熵 7.999 | ❌ 未覆盖 | 主界面混音台标注、内置插件面板（Compressor/Reverb/MultiTap）、部分对话框正文以**加密位图**形式存放，运行期解密绘制。进程内存中搜不到对应 ASCII/UTF-16 明文，字符串补丁对此层完全无效 |

判断方法：先对 exe 文件 grep 明文；命中则在字符串层。若文件里搜不到、运行后内存里也搜不到，基本可判定为加密资源/位图。

### 4.2 内存补丁流程

```
启动器 Main()
 ├─ 定位目标 exe（FindTarget 三候选：Program Files (x86) → Program Files → 启动器同目录）
 ├─ 若同名进程已运行 → MessageBox 询问是否关闭重启（Kill + 等待 800ms）
 ├─ CreateProcess(exePath, ..., CREATE_SUSPENDED=0x00000004)   ← 主线程挂起
 ├─ ApplyPatches(hProcess)
 │   ├─ NtQueryInformationProcess(ProcessBasicInformation) → PEB
 │   ├─ ReadProcessMemory(PEB + 0x10) → ImageBase（x64 为 0x140000000）
 │   ├─ 解码内嵌 base64 blob
 │   └─ 逐条：VirtualProtectEx(PAGE_EXECUTE_READWRITE)
 │            → WriteProcessMemory(ImageBase + rva, bytes + "\0")
 │            → 恢复原页保护
 ├─ ResumeThread(hThread)                                      ← 此时才执行程序代码
 ├─ CloseHandle(hThread/hProcess)
 └─ 若 patched=false → 提示"补丁未能应用，已按原版英文启动"
```

关键点：

- `ImageBase + RVA` 即目标虚拟地址；RVA 由文件偏移换算（见 §4.3）。
- 必须在 `ResumeThread` 之前写完，程序一旦开始跑，字符串可能已被读取缓存。
- 写入页需临时改为可写可执行，写完立刻还原，避免触发异常。
- 启动器本身需要管理员权限（写入另一个进程 + 目标位于 Program Files）。

### 4.3 文件偏移 → RVA

从 PE 头读节表，逐节匹配：

```
pe   = u32 @ 0x3C
nsec = u16 @ pe+6
so   = pe + 24 + u16 @ pe+20           # 节表起始
每节 40 字节：vs, va, rs, ra = u32 × 4 @ so+i*40+8
若 ra <= off < ra + rs:  rva = off - ra + va
```

### 4.4 blob 二进制格式

```
重复 N 次，直到文件末尾：
┌──────────┬──────────┬────────┬─────────────────┐
│ rva u32  │ len u16  │ enc u8 │ bytes[len]      │
└──────────┴──────────┴────────┴─────────────────┘
enc = 0 → ANSI/GBK（写完后补 1 字节 \0）
enc = 1 → UTF-16LE（写完后补 2 字节 \0\0）

当前 v4 blob：1043 条 / 21,582 字节 / base64 28,776 字符
其中 ANSI 972 条、UTF-16LE 71 条
```

约束：中文编码后长度必须 `<= 原字符串 NUL 之前的可用字节数`（GBK 双字节 + 空格余量），超长条目在生成阶段即被跳过并打印，绝不截断写入。

## 6. 构建流水线（从零复现）

### 步骤 0 · 备份原厂 exe

```powershell
Copy-Item "C:\Program Files (x86)\VB\Voicemeeter\voicemeeter8x64.exe" `
          "C:\Program Files (x86)\VB\Voicemeeter\voicemeeter8x64.exe1"
```

`.exe1` 既是生成基准，也是崩溃后的还原源。

### 步骤 1 · 扫描字符串

```powershell
python src\analysis\scan2.py     # 全量 ANSI/UTF-16 候选 → all_strings.json / ui_candidates.json
python src\analysis\scan3.py     # 补充扫描 → strings_dump.txt / utf16_strings.txt
python src\analysis\menu_dump.py # 菜单资源专项 → patch_menu.json
```

产出：`all_strings.json`（163.6 KB）、`ui_candidates.json`（101.4 KB）、`strings_dump.txt`（89.2 KB）等，用于人工挑选界面文本。

### 步骤 2 · 维护翻译

翻译分散在四个文件，按需新增即可：

| 文件 | 结构 | 用途 |
| --- | --- | --- |
| `patch_table.json` | `{"<偏移>": "中文"}` | 主表，偏移可写 `0x15a9a0` 或十进制 |
| `utf16_zh.py` | `U16 = {偏移: "中文"}` | UTF-16LE 资源词条 |
| `extra_zh.py` | `EXTRA = {偏移: ("原文", "中文")}` | 第二轮补齐，**生成时自动校验原文**，防止偏移错位 |
| `extra_zh2.py` | `MULTI = {...}` | 多行文本、同一位置多变体 |

术语一致性约定：内部控件标识符、API 参数名、XML 配置键、GUID、设备/驱动名称一律保留英文。

### 步骤 3 · 生成 blob

```powershell
python src\patch\gen_blob4.py
```

输出 `patch_blob_v4_b64.txt`，并打印：

```
打包成功 1043 条，跳过 N 条
原文不匹配 N 条: [...]     # EXTRA 中的原文与文件实际内容不符，需人工修
超长跳过 N 条: [...]       # 中文比原字符串长，需换更短译法
```

生成逻辑顺序：主表（应用 `SHORT` 简写替换）→ U16 → EXTRA（带原文校验）→ `samples` 系列正则自动翻译（`N samples (…)` → `N 采样(…)`）。

> `SHORT` 是超长条目的短译兜底表（如 `0x15a9a0 '复制门限'`、`0x1599d8 'A1声道%i'`），改译法时放在 `gen_blob4.py` 顶部即可。

### 步骤 4 · 生成启动器源码

```powershell
python src\launcher\gen_v6.py
```

把 `patch_blob_v4_b64.txt` 以 base64 常量形式内嵌进 C# 模板，输出 `Launcher_v6.cs`（含 SplashForm、`BLOB` 常量、`ApplyPatches`）。
**翻译一改就必须重跑这一步并重新编译**，blob 是编译期常量，不是外部文件。

### 步骤 5 · 编译

```powershell
csc.exe /nologo /target:winexe /platform:x64 /optimize+ `
        /win32manifest:app.manifest `
        /r:System.dll /r:System.Drawing.dll /r:System.Windows.Forms.dll `
        /out:VM8CN_Launcher_v6.exe Launcher_v6.cs
```

要点：`/target:winexe`（无黑框）、`/platform:x64`（必须，PE 位宽要与目标一致）、`/optimize+`、必须带 `app.manifest`（管理员权限 + DPI 感知）。

### 步骤 6 · 部署打包

```powershell
python src\launcher\deploy_v6.py
```

做四件事：取 `VM8CN_Launcher_v6.exe` → 改名为 `Voicemeeter8中文启动器.exe` → 以 UTF-8-SIG + CRLF 写出 `使用说明.txt` 与 `分享介绍.md` → 打包包含 4 个文件的 `Voicemeeter中文启动器_V1.0_分享包.zip`。

### 步骤 7 · 验证

```powershell
python src\test\test_v6.py
```

流程：清理旧进程 → 启动启动器 → `shot_win.py` 用 `PrintWindow` 抓窗口位图 → 转 PNG → 用 PIL 放大底部区域核验文字与布局。验收标准：

| 检查项 | 期望 |
| --- | --- |
| 启动画面出现时延 | ≈0.37 s |
| 启动画面停留 | ≈5 s 后自动消失（点击可跳过） |
| 主界面 | 菜单/提示为中文 |
| 进程稳定性 | 运行 60 s 无 `0xC0000005`/`0xC000041D` |

## 7. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动约 10 秒崩溃（0xC0000005 / 0xC000041D） | 磁盘 exe 曾被老办法直接改过，完整性校验失败 | 用同目录 `voicemeeter8x64.exe1` 覆盖还原 |
| 提示"未找到 voicemeeter8x64.exe" | 非标准安装路径 | 把启动器放到 exe 同目录，或把目标路径作为第一个命令行参数传入 |
| 提示"补丁未能应用，已按原版启动" | `ApplyPatches` 抛异常 / 未拿到 PEB / 权限不足 | 确认以管理员运行；用 `mem_patch_full.py` 单独验证注入逻辑 |
| 部分位置仍是英文 | 该文本在 RCDATA 加密资源层（§8），或尚未翻译 | 用 `memsniff.py` 确认是否为字符串层 |
| 中文乱码 | 编码选错（ANSI 位置写了 UTF-16 或反之） | 检查对应偏移的 `enc`：普通 zstring 用 GBK，宽字符资源用 UTF-16LE |
| 某条目生成时被"超长跳过" | 中文编码后字节数超原容量 | 换短译法（必要时加进 `SHORT`），不要截断写入 |
| 启动器编译报 manifest 相关错误 | 缺少 `app.manifest` 或路径不对 | 在 `src\launcher` 目录下执行编译，保持相对路径 |
| UAC 每次都弹 | manifest 声明了 `requireAdministrator`，属设计如此 | 不能取消，写入其他进程内存需要提权 |

## 8. 未覆盖部分（后续方向）

RCDATA 资源块 100–104（约 8.3 MB，熵 7.999）以加密/压缩形式存放主界面图形文字，**字符串层补丁对其零效果**。要覆盖需要一个独立的解密链：

1. 在 `voicemeeter8x64.exe` 中定位解密例程（IDA/Ghidra 交叉引用 `FindResource/LoadResource` 调用点）；
2. 提取密钥与算法，离线解出位图，替换文字后重新加密回填；
3. 或在运行期挂接解密函数返回值，把解密后的内存位图改写后再交给绘制。

注意这条路属于**资源层改造**，风险远高于内存字符串补丁，且必须严格保持校验逻辑通过（拷贝长度、熵特征变化都可能被检测）。

## 11. 授权与激活帮助面板（V1.1）

### 11.1 为什么做这块

Voicemeeter 是捐赠式（Donationware）软件，采用**单设备绑定的挑战码 / 响应码**授权：
挑战码由 CPU、主板等核心硬件生成，换硬件、重装系统、系统大版本更新、改机器名甚至更新显卡驱动
都可能让它变掉，一变授权就失效。用户实际遇到的坑集中在三件事：

1. 不知道什么操作会让挑战码变；
2. 变了不知道还有「恢复硬件足迹」这条低成本路径；
3. 不知道 REGEN 的次数、赠送记录和 2026 年 6 月起的付费规则。

这些都写在官方页面和历年邮件里，散且是英文。于是把结论固化进启动器的离线面板，
顺手把「激活日志在哪、怎么复制路径给官方」做成按钮。

### 11.3 两个入口

- 启动画面按钮：`SplashForm` 增加 `LBtnRect`（`Rectangle(40, H-84-48, 340, 32)`）与 `LicenseRequested` 标志，

### 11.4 生成脚本的坑（`gen_v7.py`）

`gen_v7.py` 用字符串替换在 `Launcher_v6.cs` 基础上插代码，踩过两处：

1. **方法结尾匹配错位**：用 `"        }" + nl` 匹配方法末尾，实际文本是 `nl + "        }" + nl`，
   替换点算错导致 CS1519 / CS1518 / CS0116 / CS1022 一片报错。改为 `nl + "        }" + nl` 并计入长度。
2. **绘制代码插进了方法体**：`OnPaint` 绘制按钮的插入锚点漏了前导换行，代码被塞进别的方法里，
   编译报 CS0103 `g` 不存在。锚点改成 `nl + "            int py = H - 84;"`。

结论：这类脚本生成式改造，锚点必须带换行上下文，改完必须立刻编译验证，不能只看文本替换成功。

### 11.5 验证方法（可复用）

不靠肉眼盯全屏截图（桌面窗口一堆，容易误判），改用**按窗口句柄截图**：

## 12. 一键打开配置目录（V1.2）

### 12.1 需求与实现

Voicemeeter 的默认配置保存在 `%APPDATA%\VoiceMeeterPotatoDefault.xml`（约 300 KB），
备份、迁移、对比时经常要打开它，但 `AppData` 是隐藏目录，用户基本找不到。V1.2 给了两个入口：

| 入口 | 位置 | 控件 |
| --- | --- | --- |
| 启动画面 | 右下角 | `CBtnRect` = `Rectangle(392, H-84-48, 168, 32)`，与左侧帮助按钮同一基线、左右并列 |
| 帮助面板 | 底部第 3 个按钮 | `MkBtn("打开配置目录", 296, 12, 124)` |

两个入口共用命名空间级静态类 `ConfigInfo`：

````csharp
static class ConfigInfo
{
    static string ConfigFile()
    {
        return Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData),
            "VoiceMeeterPotatoDefault.xml");
    }

    internal static void OpenConfigDir()
    {
        // 文件存在   -> Process.Start("explorer.exe", "/select,\"<文件全路径>\"")
        // 文件不存在 -> 打开所在目录 + MessageBox 提示「启动一次 Voicemeeter 后生成」
    }
}
````

坑：`/select,` 与路径之间**不能加空格**，且路径含空格时必须用双引号包住整段
（`/select,"C:\...\VoiceMeeterPotatoDefault.xml"`），否则资源管理器只会打开「我的文档」。

### 12.2 底部按钮重排

原 3 按钮宽 156 / 124 / 92（x = 20 / 188 / 324），插入第 4 个后改为 148 / 112 / 124 / 80
（x = 20 / 176 / 296 / 428）。客户区 820 宽，四按钮右边界 508，与右下角「第三方汉化工具，非 VB-Audio 官方产品」
小字不冲突；实测截图四个按钮间隔均匀、无重叠。

### 12.3 启动画面点按钮后为什么要 `return`

`OnMouseClick` 先判 `CBtnRect`，命中即 `ConfigInfo.OpenConfigDir(); return;` —— **必须直接返回**，
不能落到后面的 `ticker.Stop(); Close();`。否则资源管理器刚弹出，启动画面就关闭并进入注入流程，
用户会误判「点错了」。左侧帮助按钮相反：命中后要关掉启动画面并切到面板。

### 12.4 验证

`click_v8.ps1`：`EnumChildWindows` 取类名含 `BUTTON` 的子窗口 → 按 `(Y, X)` 排序 →
底部第 3 个（绝对索引 8）`SendMessage(h, 0x00F5, 0, 0)` → 枚举新增顶层窗口。
期望出现 `CabinetWClass | Roaming`，说明资源管理器已定位到 `C:\Users\<用户>\AppData\Roaming`
并选中 XML。启动画面侧用 `PrintWindow` 截图确认第二个圆角按钮文字与间距。
